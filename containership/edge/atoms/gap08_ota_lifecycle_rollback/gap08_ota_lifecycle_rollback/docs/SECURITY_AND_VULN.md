# SBOM and vulnerability response (component 38)

## Inventory

`release/SBOM.cdx.json` (CycloneDX 1.5) is generated by `tools/release_evidence.py build`. Runtime dependencies: **CPython ≥ 3.10 standard library only**. `pk_core` is optional and only imported by `component.py` / `contract.py`.

## Scanning

* Dependency scan: nothing third-party to scan in the runtime; scan the CPython runtime image used in deployment with the organisation's scanner (e.g. Grype/Trivy) on every release and weekly.
* Secret scan: `secrets_boundary.find_secrets` guards persisted data at runtime; add a repository secret scanner to CI (not included here).
* Static analysis: run `python -m compileall` and a linter/type-checker in CI (`tools/ci.sh` runs compileall + the full suite + evidence verification).

## Patch SLAs (proposed; owner to ratify)

| Severity (CVSS / exploitability) | Fix available → signed release | Fleet rollout of fix |
|---|---|---|
| Critical, exploited | 48 h | via GAP-08 emergency rollout, 72 h |
| Critical | 7 days | 14 days |
| High | 30 days | 45 days |
| Medium/Low | next scheduled release | with release |

## Emergency release path

1. Triage and impact analysis (does the flaw reach a GAP-08 trust boundary?).
2. Patch, full test suite, `release_evidence.py build` with the release key.
3. Security owner approves; release manager signs.
4. Roll the controller itself out with a canary + rollback plan; controllers are stateless apart from the store/lease/sink.

## End-of-life

A GAP-08 minor version is supported until two newer minors exist or 12 months, whichever is later. `PK_CONTROLLER_STATE` N-1 is always readable by N.
