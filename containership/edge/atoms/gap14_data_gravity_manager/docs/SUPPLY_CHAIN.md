# Dependency and Supply-Chain Policy (G14-P1-26)

* **Runtime dependencies: none** (stdlib only). Any addition requires SR approval, an exact version pin **and** a hash pin (`pip --require-hashes`), and an SBOM update.
* **Optional:** `pk_core` for the conformance gate — pinned by version range *and* tree digest in `compat.PKCORE_PIN`; the handshake refuses imports from user-site or non-allow-listed paths.
* **Build:** `pyproject.toml` pins the build backend (`setuptools==75.8.0`).
* **Integrity:** `MANIFEST.sha256` (per-file SHA-256) and `evidence/release_evidence.json` (tree digest) are regenerated by `tools/release_evidence.py`; `evidence/SBOM.cdx.json` is CycloneDX 1.5.
* **Signing:** release artifacts MUST be signed by the estate release signer (Sigstore/cosign or estate PKI) and the signature recorded in `release_evidence.json`. **Not done in this package** — `signature: null` is recorded honestly.
* **Vulnerability scanning:** with zero third-party dependencies the scan surface is CPython itself; CI must track CPython security releases for the supported range.
* **CI enforcement (required for P1 closure):** fail the pipeline if `MANIFEST.sha256` differs from a fresh computation, if any test fails or is skipped without an approved reason, or if the SBOM lists an unapproved component.
