## 2. Error precedence (as implemented)

When several conditions hold at once, the first matching check wins. This is normative: it is the order in the code and changing it is a breaking change.

### 2.1 `Stream.write`

1. `reader_dropped` → `EndDropped(end="reader")`
2. `writer_dropped` → `EndDropped(end="writer")`
3. `ended` → `StreamClosed`
4. `frozen` → `StreamFrozen`
5. type mismatch → `ElementTypeMismatch`
6. idempotency key: malformed → `ValueError`; duplicate within window → return `False` (no credit/buffer checks)
7. `credit <= 0` → `CreditExhausted` (increments `credit_stalls`)
8. `len(buffer) >= max_buffer` → `BufferLimitExceeded`

Consequence: a mistyped retry raises `ElementTypeMismatch` even if its key is a duplicate; a correctly typed duplicate is acknowledged even on a creditless or full stream; a mistyped element on a creditless stream reports the type error, not credit exhaustion.

### 2.2 `Stream.grant`

argument validation (`ValueError`) → `reader_dropped` (`EndDropped`) → `ended` or `writer_dropped` (`StreamClosed`) → `frozen` (`StreamFrozen`) → ceiling (`CreditLimitExceeded`).

### 2.3 `Stream.read`

`reader_dropped` (`EndDropped`) → buffered value → `writer_dropped` (`EndDropped`) → `ended` (`None`) → `NOT_READY`. Frozen does not block reads.

### 2.4 `StreamRegistry.write` (control plane, before 2.1)

`disabled` or quarantined scope (`ComponentDisabled`) → unknown id (`StreamNotFound`) → cross-tenant/workload (`AuthzDenied`) → token verification (`TrustServiceUnavailable` / `AuthError` / `TokenReplay` / `AuthzDenied`) → tenant `max_buffered` (`QuotaExceeded`) → instance `global_buffer_budget` (`LoadShed`, breaker failure) → §2.1.

### 2.5 `StreamRegistry.open`

gate (`ComponentDisabled`) → authorisation → version negotiation (`VersionUnsupported`) → duplicate id (`StreamError`) → breaker (`CircuitOpen`) → tenant `max_streams` (`QuotaExceeded`).
