## Authentication
- **mTLS SPIFFE** (mesh-presented): strict `map_identity`; bindings in config give actor type, roles and explicit extra tenants. Unbound workloads authenticate but hold no roles.
- **Signed token** (operator/CI/auditor): `b64(claims).b64(HMAC-SHA256)`; claims `sub, typ, aud=inv58, iat, exp (≤900 s TTL), nonce, roles, tenant/tenants`; ±30 s skew; single-use nonce (bounded cache — saturation fails closed). Tokens can never claim `node` or `workload`.
- Credentials carrying both a SAN and a token are refused (ambiguous).

## Authorization
Deny by default. An operation absent from the matrix, an unknown role, a wrong mechanism, a wrong actor type, a missing capability, a stale policy (older than `policy.max_age_s`) or a tenant outside the principal's scope is denied with a stable code from `authz.DENY_CODES`. `control.break_glass` needs its dedicated role *and* an armed window (≤1 h). Every denial and every privileged allow is audited with actor, target, capability, policy version, decision code and correlation id.

## Operational semantics
- **Timeout:** each call has `deadline_ms.default` (max `deadline_ms.max`); `execute_with_retry` refuses a backoff that would cross the deadline (`E_DEADLINE_EXCEEDED`).
- **Cancellation:** `CancelToken`; checked before each attempt and during backoff (`E_CANCELLED`).
- **Retry:** only one layer; the executor retries only idempotent methods or calls with an idempotency key, and only for pre-response failure classes; full-jitter exponential backoff bounded per delay and in total.
- **Idempotency:** `route.migrate` requires an 8–128 char key; the same key+request replays the stored result (`replayed: true`); the same key with a different request is `E_CONFLICT`; a concurrent duplicate while the first is executing is `E_CONFLICT` (retryable).
- **Backpressure:** token bucket + in-flight ceiling + per-tenant share → `E_OVERLOADED` (retryable). Circuit breakers per dependency → `E_CIRCUIT_OPEN`.

## Errors
`PK_MESH_ERROR/1` envelope: `code, outcome, retryable, status, message (sanitised, ≤256), details (bounded, scalars only), correlation_id (= trace id)`. Codes: `errors.ERROR_CODES` (append-only).

## Versions
Supported: `INTERFACE_VERSIONS` in `service.py`. Omitted version → newest supported. Unknown → `E_UNSUPPORTED_VERSION` with the supported list in details. Peers on 4.2.0 speak the same `/1` payloads; only the stricter SPIFFE charset differs (DEP-01).

| metric label values | 1 000 | `limits.max_label_cardinality` |

| idempotency cache | 10 000 keys | constructor |

## Fixtures
`fixtures/<interface>/*.json` hold golden request/response/error cases generated by `tools/gen_fixtures.py`; CI runs `--check` so any behavioural drift fails.
