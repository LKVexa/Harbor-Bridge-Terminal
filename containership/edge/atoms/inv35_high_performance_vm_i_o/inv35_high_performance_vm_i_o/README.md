# INV-35 - High-performance VM I/O

**Version:** 4.3.0  
**Group:** 01_Source_Inventory  
**Series:** Post-Kubernetes Master Prompt & Workflow Series v4.0.0  
**Checklist:** 100 requirements across ten dimensions in `CHECKLIST.json`

This package models the security-critical invariants of a high-performance VM I/O datapath: guest-controlled descriptor rings, registered guest-memory bounds, bounded queue occupancy, and notification suppression that must not strand live work. The supplied implementation is a reference/conformance model, not a production virtio/vhost backend.

## Responsibility

Own the guest-host I/O datapath safety boundary: validate every descriptor a guest places on a ring against registered guest memory, bound in-flight descriptor entries per queue, reject malformed chains before state mutation, and preserve completion-notification liveness.

## Owns

- Virtqueue descriptor validation.
- Guest-memory range validation across registered regions.
- Per-chain and per-queue descriptor bounds.
- Notification-suppression correctness in the reference policy.
- Fail-closed handling of malformed indices, loops, dangling links, invalid field types, and out-of-bounds addresses.

## Explicitly does not own

- Device semantics or guest drivers.
- Network/storage backend semantics.
- Hypervisor placement and device-model membership.
- Production virtio/vhost implementation details.
- The external `pk_core` certification framework.

## Verification

```text
python verify.py            # or VERIFY.cmd on Windows
```

| Exit | Verdict | Meaning |
|---|---|---|
| 0 | `VERIFY=PASS` | every technical and production gate satisfied |
| 1 | `VERIFY=FAIL` | compile, schema drift, test, RTM, manifest or performance failure |
| 2 | `VERIFY=PARTIAL` | technical checks pass; production blockers remain (skipped pk_core tests, governance, unsealed evidence, rollout drill) |

The gate writes `conformance/PK_GATE_RESULTS.json` (sealed when `INV35_EVIDENCE_KEY` is set) and
`python tools/exit_summary.py` regenerates the human summary from it. Criteria: `docs/operations/PRODUCTION_EXIT_GATE.md`.

Other commands:

```text
python -m unittest discover -s tests          # all suites
python benchmarks/bench.py --quick            # benchmark + threshold gate
python tools/inv35ctl.py smoke                # run every conformance fixture
python tools/gen_schemas.py --check           # schema drift
python tools/build_rtm.py --check             # RTM / audit-matrix drift
```

When `pk_core` is present (`PK_CORE_PATH`), `tests/test_component.py` runs instead of skipping.
