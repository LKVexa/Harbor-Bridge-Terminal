# INV-35 Performance model and evidence (C061–C070)

**Scope warning.** All numbers below measure the dependency-free CPython
reference implementation. They characterise the *cost of the safety and policy
logic*, not virtio/vhost line rate. Production thresholds (N-06: p50 ≥ 90 % of
line rate) belong to the backend and are waived here under WVR-003.

## Reproducible baseline (C061)

`python benchmarks/bench.py --out benchmarks/baselines/baseline-<ver>-<impl><py>-<arch>.json`

Baseline `baseline-4.3.0-cpython3.11-x86_64.json` (Linux x86_64, CPython 3.11.15, 20 000 iterations):
see the file for full percentiles; headline values are regenerated by CI.
Host metadata (python, implementation, machine, platform) is recorded in every report.
Storage/network/power dimensions do not apply to the reference model (no I/O);
they are backend-measured (C068 waiver WVR-001).

## Thresholds (C062) and regression gate (C070)

`benchmarks/thresholds.json` holds absolute p50/p99 ceilings (≈5× baseline to
absorb CI variance), a facade/raw overhead ceiling (12×) and a tenant fairness
ceiling (2×). `tests/performance/test_perf_gate.py` runs the quick benchmark on
every verification; any breach fails the gate. Worst-case (`max_us`) is recorded
but not gated (GC/scheduler noise).

## Benchmark matrix (C063, C088)

| Scenario | Key | What it shows |
|---|---|---|
| steady | `steady_raw_model_4desc`, `steady_facade_4desc` | per-cycle cost, raw vs full policy stack |
| chain sweep | `chain_sweep_{1,8,16}desc` | validation is O(chain length) |
| burst | `burst_64_fill_drain` | fill to depth and drain |
| overload | `overload_refusal`, `overload_state_intact` | refusals are cheap and non-mutating |
| scale | `scale_8x4_per_tenant_p50_us`, `scale_tenant_fairness_spread` | 8 tenants × 4 queues |
| recovery | `recovery_replay_32_us` | crash-recovery cost |
| startup/memory | `startup_16_queues_us`, `startup_peak_bytes` | cold start, peak allocation |

Soak: set `INV35_STRESS_OPS=200000` / `INV35_FUZZ_ITERS=1000000` for long runs.
Fleet scale is simulated by the scale scenario; real fleet runs are backend-owned.

## Per-workload / per-tenant overhead (C064)

`facade_overhead_ratio_p50` isolates the cost INV-35's policy stack adds over
raw validation; `scale_8x4_per_tenant_p50_us` shows per-tenant cost is uniform
(no tenant pays for another's state).

## Datapath copy / serialisation / context-switch / hop analysis (C065)

| Step (submit) | Copies | Serialisation | Context switches | Notes |
|---|---|---|---|---|
| guest writes ring | 0 (shared memory) | none | 0 | |
| notify (kick) | 0 | none | 1 guest→host (eventfd/ioeventfd) | suppressed when possible |
| snapshot descriptors | 1 × descriptor metadata (16 B each) | none | 0 | **mandatory** TOCTOU copy |
| capability check | 0 (cached) / 1 base64+JSON decode (uncached) | JSON (control only) | 0 | cache added in 4.3.0 |
| validation | 0 | none | 0 | O(chain × regions) |
| backend hand-off | 0 (payload never copied by INV-35) | none | 0–1 (vhost thread) | backend-owned |
| completion + notify | 0 | none | 0–1 host→guest (irqfd) | liveness rule |

Payload bytes are never copied or serialised by INV-35; only descriptor metadata is.

## Measured optimisation (C066)

| Optimisation | Before | After | Change |
|---|---|---|---|
| Verified-capability cache (crypto verification once per reusable token; validity/scope still checked every call) | facade p50 ≈ 100 µs, ratio 14.6× | p50 ≈ 42 µs, ratio 5.7× | −58 % p50 |

Profiled with cProfile: `Authority.authorize` was 42 % of facade time before the
cache. Batching of completions and zero-copy/kernel-bypass are backend
optimisations (WVR-003).

## Power/thermal (C068)

Not measurable in the reference model. Method for backend owners: RAPL/`powercap`
package energy per 10⁶ descriptors at steady/burst on a far-edge SKU, thermal
throttling onset under sustained overload; results go to `benchmarks/results/`.
Deferred under **WVR-001** (expires 2026-12-31).

## Capacity model and saturation signals (C069)

Capacity per host = `host_descriptor_capacity` descriptors in flight. Throughput
bound ≈ capacity / mean service time. Saturation signal `inv35_saturation`
(0–1) plus `inv35_queue_depth{queue}` and E200/E201 refusal rates. Alert
thresholds in `alerts/inv35_alerts.json`.
