# ADR-002: Trusted time with persisted high-water mark

**Status:** Proposed (2026-09-22) — requires architecture + security owner acceptance (see `../GOVERNANCE.md`). Superseding decisions must add a new ADR; this file is not rewritten in place.
**Controls:** C02 · **Modules:** runtime/clock.py

## Context
Lease expiry and policy staleness depend on elapsed time an attacker can manipulate.

## Decision
All safety timing uses `TrustedClock` (integer seconds). Anchors: signed nonce-bound time tokens or authenticated time adapters; monotonic extrapolation in between; persisted HWM makes time non-decreasing across restarts (restored HWM += persist interval). No anchor after reboot = fail closed (optional RTC fallback caps at freeze).

## Alternatives considered and rejected
(a) Wall clock (4.2.0 caller-supplied ticks). (b) TPM NV counters — preferred, but no hardware in scope; seam kept (W-012).

## Consequences
* Security: see `../THREAT_MODEL.md` for residual risks linked to this decision.
* Operations: see `../RUNBOOK.md`.
* Compatibility/migration: persisted and wire formats are versioned; see `../../COMPATIBILITY_MATRIX.json`.
* Verification: tests referenced in `../../evidence/CHECKLIST_STATUS.json` for the controls above.
