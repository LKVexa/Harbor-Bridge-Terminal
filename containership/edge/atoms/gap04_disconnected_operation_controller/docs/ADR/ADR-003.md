# ADR-003: Persistence substrate: single append-only WAL with snapshot+delta frames

**Status:** Proposed (2026-09-22) — requires architecture + security owner acceptance (see `../GOVERNANCE.md`). Superseding decisions must add a new ADR; this file is not rewritten in place.
**Controls:** C03, C17, C18, C20 · **Modules:** runtime/journal.py, runtime/storage.py, runtime/node.py:_recover

## Context
State (lease/policy/epoch/decisions) must never tear across a crash.

## Decision
One file `journal.wal`; every transaction is exactly one CRC-framed, hash-chained, HMAC'd, fsync'ed frame. Control events carry a full state snapshot; decisions are delta frames replayed onto the last snapshot for the open partition epoch. Compaction writes a MAC'd anchor header + retained frames atomically (tmp+fsync+rename+dir fsync).

## Alternatives considered and rejected
(a) SQLite — larger dependency, weaker tamper evidence, WAL semantics harder to reason about under the audit requirement. (b) Full snapshot per decision — tried first; O(n²) storage and frame overflow found by tests, rejected.
