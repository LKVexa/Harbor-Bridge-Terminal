# ADR-006: Fencing: exclusive OS lock + persisted generation on every side effect

**Status:** Proposed (2026-09-22) — requires architecture + security owner acceptance (see `../GOVERNANCE.md`). Superseding decisions must add a new ADR; this file is not rewritten in place.
**Controls:** C16, C17 · **Modules:** runtime/fencing.py

## Context
Duplicate or stale controllers must not act.

## Decision
Acquisition bumps a persisted generation; every frame and supervisor command carries it; journal append refuses a generation lower than persisted; downstream validators keep the max (epoch, generation) seen.

## Alternatives considered and rejected
(a) PID files — not safe. (b) External consensus lease — required for multi-host (W-011), out of scope for the single-host reference.

## Consequences
* Security: see `../THREAT_MODEL.md` for residual risks linked to this decision.
* Operations: see `../RUNBOOK.md`.
* Compatibility/migration: persisted and wire formats are versioned; see `../../COMPATIBILITY_MATRIX.json`.
* Verification: tests referenced in `../../evidence/CHECKLIST_STATUS.json` for the controls above.
