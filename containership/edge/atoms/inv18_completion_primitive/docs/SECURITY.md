# INV-18 security specification (C041–C050)

The canonical threat model is `conformance/THREAT_MODEL.json` (20 threats, each mapped
to mitigations and executed tests; `approved_by` is null until the security owner signs).
This document explains it.

## 1. Threat model summary (C041)

Assets: resolution record, receiver ownership, capability tokens, tenant isolation,
audit chain, release evidence, host availability. Trust boundaries: in-process
capability API, wire adapter, pk_core/supply chain, configuration input, release
pipeline. Actors and threats T01–T20 cover malicious tenants, compromised
producers/consumers, hostile payloads, compromised pk_core, supply chain, control plane,
DoS, replay, capability theft, cross-tenant access and diagnostic leakage. Residual
risks are listed in the JSON.

## 2. Identities and least privilege (C042)

| Identity | Capabilities | Filesystem | Network | Env | Secrets |
|---|---|---|---|---|---|
| producer | resolve, resolve_error, abandon (one future) | none | none | none | none |
| consumer | take, wait, cancel (one future) | none | none | none | none |
| observer | inspect (one future) | none | none | none | none |
| operator | administer (disable/enable), config activate | reads config file (CLI only) | none | `INV18_CFG_*` only | `secret://` refs only |
| wire client | per-token `cap` list | — | adapter host | — | signing key via KeyRing |
| release pipeline | writes evidence/ | evidence dir | none | `INV18_RELEASE_KEY` (optional) | release key |

Removed permissions fail safely: a missing capability yields `PERMISSION_DENIED`
without side effects (tests/test_runtime.py::CapabilityTest). Periodic review: REVIEWS.json.

## 3. Ambient authority (C043)

`future.py, errors.py, runtime.py, config.py (except load_file/from_env), telemetry.py,
wire.py, retry.py, auth.py, adapters.py, adjacent.py, status.py` perform no filesystem,
network, device, subprocess or secret access. Verified two ways
(tests/test_security.py::AuthorityTest): an AST inventory of imports/calls against an
allow-list, and a runtime sandbox that patches `open`, `socket.socket`,
`subprocess.Popen`, `os.system` and `os.environ` access to raise while the full
lifecycle runs. Unavoidable authority, with rationale: `os.urandom` (token entropy),
`time` (latency telemetry), `threading` (the lock itself), `config.load_file` /
`config.from_env` (operator-invoked only), `status.lineage` (reads the package's own
conformance/LINEAGE.json). No dynamic imports except the lazy `pk_core` integration (`__init__.py`) and `future.py`'s
standalone-load fallback, which loads its sibling `errors.py` by path only when `future.py`
itself was loaded by path (isolation tests).

## 4. Authentication (C044)

Implemented in `auth.py` for the only remote boundary. Verified before state mutation;
issuer/audience/expiry/ttl/nonce checked; anonymous calls impossible (a token is
mandatory); identity comes only from verified claims (`sub`), never from `tenant` fields
in the body (mismatch → PERMISSION_DENIED); rotation without downtime via key overlap.
Attestation/certificates: delegated to the mTLS layer of the host (residual risk).

## 5. Artifact integrity and provenance (C045)

`SHA256SUMS` covers every shipped file; `conformance/SBOM.json` (CycloneDX-shaped,
generated by tools/sbom.py) lists components and digests; `requirements.lock.json` pins
dependencies (the stdlib only, plus pk_core — BLOCKED); `tools/gate.py` records source
digest, build environment identity, input digests and seals the evidence (SHA-256 chain
+ HMAC when `INV18_RELEASE_KEY` is provided — otherwise the gate reports the condition
`UNSIGNED_EVIDENCE`). `tools/verify.py` rejects any file whose digest differs.

## 6. Tenant isolation (C046) and encryption (C047)

Multitenancy is applicable to the governed Runtime. Every future is bound to a tenant;
capabilities of tenant A are refused for tenant B's future with the same response as a
non-existent future (anti-enumeration); per-tenant quotas bound resource use; logs carry
only a hashed tenant id. Memory separation: separate registry entries, no shared payload
objects. Payload sensitivity is *caller-defined* → treated as confidential. At rest:
N/A — the core never persists anything. In transit: the wire adapter must run under
mTLS (`network_exposure=mtls` requires `signing_key_ref`); approved policy: TLS 1.3,
HMAC-SHA256 tokens, keys ≥ 256 bits from the secret store, rotation every 90 days with a
24 h overlap, revocation via `KeyRing.revoke`. Keys never appear in logs/evidence
(`KeyRing.__repr__` prints kids only).

## 7. Security-service outage behaviour (C048)

| Service unavailable | Behaviour |
|---|---|
| identity / key service | fail closed: `DEPENDENCY_UNAVAILABLE`, no mutation |
| authorization policy | capabilities are local; no remote policy — N/A |
| attestation | delegated to host mTLS; adapter refuses to start with `network_exposure=mtls` and no key ref |
| trusted time | fail closed (`time_trusted` hook) |
| cached policy | max stale age `policy_max_stale_s` (300 s) — no cached credentials are used |
Fail-open exceptions: **none**. Status shows the dependency state.

## 8. Audit (C049)

Events: `auth.failure`, `capability.denied`, `admin.denied`, `component.disable/enable`,
`config.activate/rollback`, `ownership.fence`, `invariant.violation`, `runtime.start`.
Schema `PK_FUTURE_AUDIT/1`: seq, event_id, ts, actor, action, target, result,
correlation_id, redacted details, prev hash, hash, optional HMAC. `AuditChain.verify`
detects mutation, deletion and reordering.

## 9. Adversarial suite (C050, C087)

tests/test_security.py — privilege escalation, capability forgery, cross-tenant access,
injection, replay, spoofed identity, malformed schema, oversize, exhaustion,
high-concurrency flood, timing (constant-time comparison enforced statically),
dependency tampering, secret leakage. Sandbox escape: N/A (no sandbox is provided by the
primitive). Every negative test asserts a *structured* code, i.e. fails securely.
