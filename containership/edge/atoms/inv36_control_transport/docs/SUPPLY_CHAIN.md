Approved source: PyPI (or the organisation mirror) over TLS; no VCS or URL dependencies. `pip-audit` runs on every PR and nightly (CI job `security`); findings SLA: critical 72 h, high 7 d, medium 30 d, low next release (see `docs/GOVERNANCE.md`). Dependency drift in release builds is prevented by installing only from the hash-pinned lock with `--require-hashes` (the lock is generated by CI because the authoring environment had no registry access - debt D-005).

## Build, SBOM, provenance, signing

`tools/release.py`:

- `build` - wheel + sdist from `git archive HEAD` (never a dirty tree), `SOURCE_DATE_EPOCH` from the commit, then a manifest check against `release/manifest.json` (required files present; keys, caches, evidence, dist forbidden).
- `sbom` - CycloneDX 1.5 JSON with component hashes, dependency versions, licenses, source commit and Python version.
- `provenance` - in-toto Statement v1 with SLSA v1 predicate: subjects (artifact digests), builder ID, invocation, source commit.
- `sign` / `verify` - Ed25519 signature over `SHA256SUMS` (artifacts + SBOM + provenance). In CI the release job signs with a managed identity (GitHub OIDC -> signing service) inside a protected `release` environment; `--key-file` is for offline releases. `verify` fails closed on missing files, digest mismatch, wrong key ID, bad signature or provenance subject mismatch.

Expected trust roots and verification instructions are published with each release (`RELEASE-VERIFY.md` generated by the release job): `python -m inv36_control_transport.tools.release verify --out <dir> --pub <hex> --key-id <id>`. Signing-identity rotation follows `docs/KEYS.md` (`release_signing`); revocation is by removing the key ID from the published trust list.

## CI hardening

Actions pinned by full commit SHA; workflow token `contents: read` by default; `id-token: write` only in the release job; release job gated by the protected `release` environment (required reviewers) and runs only on tags; PR workflows never receive secrets (`pull_request`, not `pull_request_target`); secret scanning (`tools/secret_scan.py`) and repository hygiene on every PR; scan reports and waivers retained as artifacts for 90 days (release evidence: 400 days).

Signing events are recorded as `release.sign` audit events by the release job.
