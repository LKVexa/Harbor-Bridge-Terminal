## Context

INV-36 carries small, authoritative control messages (placements, leases, revocations, drains) between a host agent and guest agents running in VMs/microVMs on the same physical host. The messages are low-volume, latency-sensitive (sub-millisecond targets), must be strictly ordered and must never be forged, replayed or read by intermediaries. Bulk data is INV-37's job; WAN relaying and NAT traversal are GAP-12's; peer attestation evidence is produced by GAP-06.

Problem statement: provide a dedicated host<->guest control channel that (a) does not depend on guest IP networking (which tenants control and which may be absent), (b) authenticates both ends cryptographically, and (c) keeps its attack surface small enough to reason about.

## Decision

1. **Transport:** virtio-vsock (`AF_VSOCK`, `SOCK_STREAM`), port 5036, via `vsock.py`. Linux only.
2. **Framing:** `PK_CTRL_STREAM/1` - version preamble plus length-delimited records with the length validated before allocation (`stream.py`).
3. **Session establishment:** `PK_CTRL_HS/1` - SIGMA-style signed-ephemeral X25519, Ed25519 identity credentials issued by an estate trust anchor, transcript-bound signatures and MAC key confirmation; exports the session secret and a 32-byte session ID (`handshake.py`).
4. **Frame protection:** existing `PK_CTRL_FRAME/2` - AES-256-GCM-SIV, HKDF-SHA-256 directional keys, exact-next 64-bit sequencing, fail-closed before wrap (`transport.py`, unchanged from 5.0.0).
5. **Envelope:** `PK_CTRL_MSG/1` canonical binary envelope carrying message type, tenant, idempotency op ID and trace context inside the AEAD (`messages.py`).
6. **Authorization:** single decision point, default deny, tenant bound to authenticated identity (`policy.py`).
7. **Wire contracts** are defined in `schema/pk_ctrl.idl.json`; code constants are generated and drift-checked.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| TCP/IP between host and guest | Requires guest network configuration that tenants control; exposes the control plane to the guest's network stack and any routed path; IP identity is spoofable inside tenant networks. |
| Unix domain sockets | Not available across the VM boundary without a shared filesystem (virtiofs), which enlarges the trust surface. |
| Shared memory (ivshmem / custom virtqueue) | Lowest latency but requires custom device/driver work, harder to audit, no standard stream semantics, portability across VMMs poor. |
| virtio-serial | Single-stream character device; no connection semantics, no multiplexing of peers, awkward reconnect; less supported in microVMs (Firecracker supports vsock, not virtio-serial). |
| gRPC over IP / TLS | Heavy dependency and parsing surface (HTTP/2, protobuf) for a tiny control vocabulary; still needs IP networking. TLS 1.3 over vsock was the closest alternative for the handshake - rejected for 5.1 because the Python stdlib `ssl` module cannot bind the exporter to the existing PK_CTRL_SESSION/2 derivation without extra native dependencies, and certificate-path validation would pull X.509 parsing into the trusted base. Revisit if a native core is adopted. |
| Noise_XX via a third-party library | Well-analysed pattern, but adds an unreviewed dependency; PK_CTRL_HS/1 uses only `cryptography` primitives already trusted by PK_CTRL_FRAME/2. |

## Trust assumptions of the vsock boundary

- The hypervisor/VMM delivers bytes between a guest CID and the host but is **not** trusted for identity: CIDs can be reassigned on migration/restore and are chosen by the VMM operator. Every connection must complete PK_CTRL_HS/1; CID/port only feed admission, churn limiting and quarantine scoping.
- A hostile guest may send arbitrary bytes, open many connections, or stall; bounds exist for each (record length, preamble, handshake size/time, connection and per-CID churn limits, penalty box).
- A hostile host process without the host agent's identity key cannot impersonate the host agent; a compromised host kernel/VMM is out of scope (it controls guest memory).

## Ordering, replay, lifetime

Strict exact-next sequencing (reordering is a protocol error on a reliable stream); replayed frames are refused without state change; application-level replays are refused by the op-ID dedup window (persisted across restarts). Sessions are never resumed: reconnect, restart, migration and snapshot restore all force a fresh handshake. Rekey (= new handshake) after `session_max_age_s` or `session_max_frames`; the sequence space cannot wrap.

## Quantified criteria used

| Criterion | Target | Evidence (reference env, not certified) |
|---|---|---|
| seal+open 64 B p99 | <= 50 us on certified target | 21 us p99 (`perf/baseline-reference.json`) |
| handshake p99 | <= 50 ms | ~3.5 ms |
| control-op round trip p99 (in-memory stream) | <= 25 ms | ~0.7 ms |
| memory per session pair | <= 256 KiB | ~24 KiB |
| attack surface | stdlib + `cryptography` only at runtime | `pyproject.toml` |
| isolation | tenant bound to credential; relay cannot alter tenant/type | tests `AuthorizationTest`, `FullStackTest` |

## Failure-mode analysis (summary)

Dependency outages fail new sessions closed while existing sessions run to max age; stream failures close the channel and trigger jittered reconnects with a shared retry budget; integrity failures close the channel and feed the penalty box; overload sheds optional traffic first. Details: `docs/RESILIENCE.md`, `docs/RECOVERY.md`.

## Consequences

- Linux-only data path; Windows (Hyper-V sockets) and macOS (Virtualization.framework) are unsupported until separate adapters exist.
- Operations must run an identity/credential issuer, revocation feed and quarantine authority key; runbooks in `docs/RUNBOOKS.md`.
- Observability, audit logging and gate evidence are part of the component, not optional add-ons.
- Python cannot zeroize key material; see `SECURITY.md`.
- Tooling maturity: `cryptography` (OpenSSL/BoringSSL-backed) is mature; the PK_CTRL_HS/1 construction is new and **requires external cryptographic review** before production certification.

## Re-review triggers

Protocol major version change; any crypto primitive change; a new hypervisor/VMM or transport adapter; any change to the trust boundary (e.g. trusting CID); material performance regression beyond `perf/thresholds.json`.
