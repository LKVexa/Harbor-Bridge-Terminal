# ADR-001 — Close GAP-09 missing components as an additive, stdlib-only overlay

- **Status:** PROPOSED (no owner has accepted it; see `WAIVERS.json` for the owner gap)
- **Date:** 2026-09-22
- **Context:** v5.0.0 is a hardened latest-value store. The 60-component checklist asks for
  real trust adapters, durability, a multi-signal pipeline, a network service and
  operational artifacts. The archive contains no `pk_core`, no sibling GAP-06/07/08,
  no Wasm runtime, hypervisor, fleet or KMS.
- **Decision:**
  1. The v5.0.0 files stay byte-identical (asserted against `MANIFEST.sha256` by a test);
     everything new lives in `components/`.
  2. Runtime stays **stdlib-only** (CPython ≥ 3.10). Optional tools are *declared test
     lanes* (`jsonschema`, `node`, `openssl`): absent → NOT_RUN with a reason, never PASS.
  3. Signatures move from HMAC fixtures to **Ed25519 over GAP09-CSP/1** (RFC 8785 JCS).
     Ed25519 is implemented in pure Python for verification; it is correct against
     RFC 8032 vectors and a Node.js reporter, but **not constant-time and slow**
     (~26 ms/verify) — waiver W-002 requires a native provider before production.
  4. The store's verifier slot is fed a pre-verified authority by `VerifiedIngest`, so the
     v5.0.0 store keeps doing scope, conflict and atomic-commit checks unchanged.
  5. A submission id is consumed once its signature verifies (signed-nonce semantics),
     even if a later check refuses the batch — conservative, documented.
  6. Checklist status is computed by `checklist/engine.py`; the engine can emit
     `VERIFYING` at most. `PASS` requires a named owner and an independent reviewer,
     neither of which exists, so every component closes `BLOCKED`.
- **Consequences:** real integration items (01, 02.12, 05 live PKI, 06, 07, 08 gateway,
  16, 17, 24/25 live runtimes, 39 multi-node, 44, 49 fleet, 51 power) remain BLOCKED on
  named dependencies. The overlay is a reference implementation of every mechanism
  those integrations must pass through.
