# Interfaces (MC-012, MC-013, MC-014, MC-016, MC-017, MC-018, MC-020)

All wire contracts are JSON Schemas in `schemas/`, generated by `tools/gen_schemas.py`. CI fails
if the generated schemas drift from the committed ones. The runtime validator (`production/schema.py`) is
stdlib-only, rejects any schema keyword it doesn't implement, and is cross-checked against the reference
`jsonschema` package in `tests/contract`.

| Protocol | Schema | Direction | Auth | Capability |
|---|---|---|---|---|
| `PK_ECP_ADMIT/1` | `PK_ECP_ADMIT_REQUEST_1`, `PK_ECP_ADMIT_DECISION_1` | client → INV-66 | JWT (EdDSA) or mTLS SPIFFE | `admit`, or `admit.dry_run` for dry runs |
| `PK_ECP_RBAC/1` | `PK_ECP_RBAC_REQUEST_1` | admin → INV-66 | JWT | `rbac.admin` at the target scope (delegation-bounded) |
| `PK_ECP_AUDIT/1` query / export | `PK_ECP_AUDIT_QUERY_1`, records `PK_ECP_AUDIT_RECORD_2` | auditor → INV-66 | JWT | `audit.read` / `audit.export` |
| `PK_ECP_CONFIG/1` | `PK_ECP_CONFIG_1` | security admin → INV-66 | JWT | `policy.admin`, `config.approve`, `config.activate` |
| `PK_ECP_HEALTH/1` | `PK_ECP_HEALTH_1` | operator | none for `/healthz`; `/readyz` should be network-restricted | — |
| `PK_ECP_INVENTORY/1` | `PK_ECP_INVENTORY_1` | reader | JWT | `inventory.read` |
| `PK_ECP_ERROR/1` | `PK_ECP_ERROR_1` + `schemas/ERROR_REGISTRY.pin` | INV-66 → any | — | — |
| `PK_ECP_DELIVER/1` | documented in `production/adapters.py` | INV-66 → INV-63 | HTTPS; mTLS identity via adapter config | INV-63 side |
| OPA data API | `{"input": ...}` → `{"result": {"allow", "reasons", "policy_version"}}` | INV-66 → GAP-13 | HTTPS | GAP-13 side |

**Principal vs payload.** The principal comes only from the credential. No request field can set
it (`tenant` in the request is the *target* scope and is checked by RBAC; a workload identity is
confined to its own tenant).

**Canonicalisation.** Manifest identity is SHA-256 over canonical JSON (sorted keys, no
whitespace, UTF-8, NaN/Infinity rejected). Identifiers are matched as exact code points against
`^[A-Za-z0-9][A-Za-z0-9_.:@\-]{0,127}$`. Unicode normalisation is deliberately **not** applied,
so confusable characters are rejected by the pattern instead of being folded.

**Unknown fields.** Requests: `additionalProperties: false`, so an unknown field is rejected. Responses:
clients must ignore unknown fields (additive minor versions).

**Idempotency / deadlines / retry (MC-017).** `request_id` is required and scoped to the caller.
`idempotency_key` is optional; it is scoped to the plane and kept in the replayed journal. Reusing a
key with a different body → `ECP_IDEMPOTENCY_CONFLICT`. `deadline_ms` defaults to
`limits.default_deadline_ms`. A request whose deadline has expired **before** the journal write
records nothing. Retryability comes from the error registry's `retryable` flag, not from message text.
Retries use capped exponential backoff with full jitter and never run past the deadline.
Overload → `ECP_OVERLOADED` (503, `Retry-After`). Quota → `ECP_QUOTA_EXCEEDED` (429, `retry_after_ms`).

**Errors (MC-016).** 32 codes, each with a stable `wire` number, a category, severity, `retryable`,
an HTTP mapping and guidance. Details go through an allow-list, and unknown exceptions become
`ECP_INTERNAL` with no internals exposed. The registry digest is pinned, so renaming or re-meaning
a code fails CI.

**Version negotiation (MC-018).** `Accept-Protocol` header. See `release/compatibility.json`
for the matrix and the frozen fixtures in `fixtures/compat/`.
