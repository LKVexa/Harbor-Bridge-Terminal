# MC-002 — Authenticated topology mutation boundary

**Modules:** `controlplane/topology_service.py`, `controlplane/authz.py`

## Scope
Only authenticated, authorized, integrity-bound, audited, rate-limited, CAS-guarded topology mutations reach the durable topology store.

## Non-goals
Discovering hardware (GAP-02); node lifecycle ownership.

## Owned by adjacent services
Identity MC-012, store MC-004, audit MC-013.

## Interfaces

| Interface | Protocol / version | AuthN/Z | Timeout | Retry | Failure semantics |
|---|---|---|---|---|---|
| TopologyService.mutate | request + GAP03-ID/1 credential (req digest claim) | Ed25519 token, aud gap03.topology; approvals aud gap03.topology.approve | caller deadline | idempotent by (sub, request_id) | GAP03-ERR/1 external payload |

## Data / state model
Request {request_id, source_service, reason, expected_generation, mutations[{op, id, node_type, parent, labels, lifecycle, replace}]}.

## Invariants → enforcing tests

- No unauthenticated or unbound request mutates topology — `test_mc002_request_integrity_binding`
- Re-parent needs a second, distinct approver — `test_mc002_rbac_and_two_person_rule_for_reparent`
- Stale or invalid batches leave no partial state — `test_mc002_stale_generation_and_invalid_batch_roll_back_atomically`
- No privileged mutation without an audit record — `test_mc002_audit_unavailable_blocks_mutation`

## Threat model (STRIDE + replay / stale-state / cross-tenant)

| Threat | Treatment |
|---|---|
| spoofing | Callers authenticate with GAP03-ID/1 Ed25519 credentials; unknown issuer/kid/alg rejected (MC-012). |
| tampering | Canonical-JSON digests bind requests/artifacts; hash-chained WAL detects on-disk edits (MC-001/004). |
| repudiation | Privileged actions are written to the tamper-evident audit log before commit (MC-013). |
| disclosure | Error payloads, logs and explain output are redacted/pseudonymised (MC-014/020/024). |
| dos | Size/depth/cardinality bounds on every input; admission + rate limits (MC-001/025). |
| elevation | Least-privilege RBAC with two-person rule for high-blast-radius operations (MC-002/017). |
| replay | Single-use nonces with bounded cache; idempotency keys return the original outcome (MC-012/026). |
| stale_state | Generation / revision / fencing preconditions reject stale decisions (MC-004/005/006). |
| cross_tenant | Tenant-scoped reads; reservations of other tenants are never spendable (MC-003/005). |

## Cryptography / secrets
Ed25519 request credentials + approvals; keys held by reference; production custody in HSM/KMS. **(production custody blocked: external HSM/KMS)**

## Sensitive data
No tenant secrets; identifiers pseudonymised in telemetry.

## Failure modes

| Failure | Behaviour | Mode |
|---|---|---|
| audit down | mutation refused | fail-closed |
| identity down | mutation refused | fail-closed |
| stale generation | STALE_STATE, client re-reads | fail-closed |
| mutation storm | per-principal/global buckets | bounded |

## Concurrency / idempotency / retry
Single writer per store under an RLock; cross-process ownership via fencing tokens (MC-006); every op idempotent by op_id; no internal retries - callers use MC-026.
