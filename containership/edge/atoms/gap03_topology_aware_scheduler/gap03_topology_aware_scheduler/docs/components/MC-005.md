# MC-005 — Durable fair-share ledger

**Modules:** `controlplane/ledger_store.py`

## Scope
Durable claims (pending/committed/released/aborted/expired) enforcing capacity + reservation invariants at the store boundary.

## Non-goals
Placement decision (SCH-01); entitlement authorship (MC-003).

## Owned by adjacent services
Commit protocol MC-007; entitlement MC-003.

## Interfaces

| Interface | Protocol / version | AuthN/Z | Timeout | Retry | Failure semantics |
|---|---|---|---|---|---|
| LedgerStore.submit(prepare|commit|abort|release|reclaim_expired|reconcile) | WAL op | fencing token | fsync-bound | idempotent by op_id | GAP03-ERR/1 outcome |

## Data / state model
capacity, reserved{tenant}, entitlement_generation, fence, claims{id: {tenant, slots, state, owner, fence, expires_at, txn}}, outcomes{op_id}.

## Invariants → enforcing tests

- used <= capacity and >= 0 always — `test_mc005_store_boundary_enforces_fairness_and_capacity`
- Replayed op never double-consumes — `test_mc005_idempotent_claim_ids`
- Concurrent claims are linearizable — `test_mc005_concurrent_claims_linearizable`

## Threat model (STRIDE + replay / stale-state / cross-tenant)

| Threat | Treatment |
|---|---|
| spoofing | Callers authenticate with GAP03-ID/1 Ed25519 credentials; unknown issuer/kid/alg rejected (MC-012). |
| tampering | Canonical-JSON digests bind requests/artifacts; hash-chained WAL detects on-disk edits (MC-001/004). |
| repudiation | Privileged actions are written to the tamper-evident audit log before commit (MC-013). |
| disclosure | Error payloads, logs and explain output are redacted/pseudonymised (MC-014/020/024). |
| dos | Size/depth/cardinality bounds on every input; admission + rate limits (MC-001/025). |
| elevation | Least-privilege RBAC with two-person rule for high-blast-radius operations (MC-002/017). |
| replay | Single-use nonces with bounded cache; idempotency keys return the original outcome (MC-012/026). |
| stale_state | Generation / revision / fencing preconditions reject stale decisions (MC-004/005/006). |
| cross_tenant | Tenant-scoped reads; reservations of other tenants are never spendable (MC-003/005). |

## Cryptography / secrets
Not applicable - holds no keys; integrity via canonical digests.

## Sensitive data
No tenant secrets; identifiers pseudonymised in telemetry.

## Failure modes

| Failure | Behaviour | Mode |
|---|---|---|
| crash mid-write | torn tail truncated on recovery; unacknowledged op never visible | fail-closed |
| disk full / read-only | store flips read-only, writes refused with DEPENDENCY_UNAVAILABLE | fail-closed |
| corrupt record mid-log | recovery refuses with INTEGRITY_FAILURE | fail-closed |
| duplicate delivery | idempotency key returns original outcome | safe |
| stale writer | fencing token / generation precondition rejects | fail-closed |
| operator error | all mutations audited; restore from verified backup (MC-042) | recoverable |

## Concurrency / idempotency / retry
Single writer per store under an RLock; cross-process ownership via fencing tokens (MC-006); every op idempotent by op_id; no internal retries - callers use MC-026.
