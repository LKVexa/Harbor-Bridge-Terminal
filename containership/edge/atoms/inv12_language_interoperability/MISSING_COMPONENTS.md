# INV-12 Language Interoperability — Missing Components

This inventory lists production components **not present in the 4.2.0 archive**. Items are split between core INV-12 functionality and the integration/assurance machinery required to prove it in production. The list intentionally does not count compilers, placement engines, composition linking, or interface authoring as INV-12-owned implementations, although integration adapters to those systems are required.

## P0 — Core semantic and ABI components

1. **MC-001 — Canonical type AST and schema loader.** Parse the authoritative interface/WIT schema into a typed graph so nested list/record/variant/option/result members can be validated recursively instead of only checking top-level shapes.
2. **MC-002 — Complete canonical primitive type set.** Add the missing signed/unsigned widths and Component Model scalar forms such as `s8`, `u16`, `s16`, `char`, plus any spec-version-required types.
3. **MC-003 — Tuple, enum, and flags model.** Provide first-class canonical representations, validation, and language mappings for tuple/enum/flags rather than encoding them informally as generic containers.
4. **MC-004 — Resource-handle type system.** Implement typed resource handles and tables, including handle identity, lifetime, invalidation, and cross-component non-alias guarantees.
5. **MC-005 — Own/borrow semantics.** Model owned versus borrowed resources/values explicitly and enforce legal borrow scopes, transfer, and post-return invalidation.
6. **MC-006 — Recursive composite validator.** Validate every field/element/case against its declared nested schema, including path-aware errors and bounded recursion.
7. **MC-007 — Language representation registry.** Replace type allowlists with versioned mappings that state the exact native representation for every canonical type in Rust, Go, JavaScript, Python, and future guests.
8. **MC-008 — Numeric conversion policy engine.** Centralize integer, float, NaN, infinity, signedness, narrowing, widening, and exactness rules per language/profile.
9. **MC-009 — Unicode and character transcoder.** Implement canonical UTF-8/Unicode scalar handling across languages with explicit invalid-sequence and normalization policy.
10. **MC-010 — Canonical binary layout engine.** Implement the actual canonical ABI memory representation, alignment, flattening, discriminants, indirect values, and lower/lift layout rules rather than Python object dictionaries.
11. **MC-011 — Guest-memory adapter.** Read/write guest linear memory safely with bounds checks, integer-overflow checks, alignment enforcement, and no host aliasing.
12. **MC-012 — Realloc/post-return lifecycle.** Implement canonical `realloc`/post-return mechanics and prove allocations are released exactly once with no leak, use-after-free, or double free.
13. **MC-013 — Variant/option/result wire model.** Define deterministic discriminants and payload layouts, reject invalid tags, and preserve case-specific type information.
14. **MC-014 — Canonical error envelope.** Serialize stable machine-readable error code, field path, source/target language, interface/type identity, retryability, and safe diagnostic detail.
15. **MC-015 — ABI/version negotiation.** Negotiate interface, canonical ABI, mapping-profile, and guest-binding versions and fail closed on unsupported combinations.
16. **MC-016 — Compatibility/evolution engine.** Detect backward/forward compatible schema changes, forbidden breaking changes, and required adapters across interface versions.
17. **MC-017 — Async/future/stream boundary semantics.** Add asynchronous values, streams, cancellation, backpressure, completion, and ownership behavior required by modern component interfaces.
18. **MC-018 — Schema-derived resource limits.** Replace only-global ceilings with per-interface/per-type limits for payload bytes, list lengths, nesting, concurrent calls, outstanding resources, and stream windows.

## P0 — Real runtime and language integrations

19. **MC-019 — WebAssembly Component Model runtime adapter.** Connect the reference semantics to an actual production component runtime and canonical ABI implementation.
20. **MC-020 — Rust binding adapter and fixture component.** Generate/use bindings and execute real Rust producer/consumer conformance fixtures.
21. **MC-021 — Go binding adapter and fixture component.** Generate/use bindings and execute real Go producer/consumer conformance fixtures.
22. **MC-022 — JavaScript binding adapter and fixture component.** Exercise Number/BigInt/string/composite/resource behavior in a real JS engine and component runtime.
23. **MC-023 — Python binding adapter and fixture component.** Define the production Python mapping layer rather than relying on the audit reference model itself.
24. **MC-024 — Cross-language conformance matrix.** Run every supported producer→consumer language pair over the same golden corpus, including boundary values and failure vectors.
25. **MC-025 — Adjacent-layer integration fixtures.** Verify INV-11 contract types, INV-10 composition calls, INV-13 host/system calls, and isolation/SFI integration using real artifacts.

## P1 — Verification, safety, and performance components

26. **MC-026 — Golden canonical test-vector corpus.** Version canonical scalar/composite/resource cases with expected lower/lift bytes, errors, and ownership outcomes.
27. **MC-027 — Property-based test harness.** Generate valid/invalid values from schemas and prove round-trip, no-loss, no-alias, and exactly-once ownership invariants.
28. **MC-028 — Coverage-guided fuzzing harness.** Fuzz parsers, lower/lift paths, discriminants, memory offsets, lengths, Unicode, resource handles, and error paths.
29. **MC-029 — Differential runtime tester.** Execute identical vectors across multiple compliant runtimes/bindings and flag semantic/layout divergence.
30. **MC-030 — Malicious-memory test harness.** Probe out-of-bounds pointers, integer overflow, overlapping regions, stale handles, misalignment, forged tags, and adversarial lengths.
31. **MC-031 — Concurrency/race stress suite.** Stress parallel transfer, cancellation, resource drop, shared registry reads, and high-contention ownership paths beyond the two-thread unit test.
32. **MC-032 — Leak/use-after-free detector integration.** Run sanitizers/runtime diagnostics around canonical allocations and resource tables for long-lived stress tests.
33. **MC-033 — Cross-platform architecture matrix.** Certify x86-64 and ARM64 at minimum, plus OS/runtime combinations and any architecture-specific ABI assumptions.
34. **MC-034 — Performance benchmark harness.** Measure scalar/composite lower+lift p50/p95/p99, allocation counts, copy bytes, and throughput using the production runtime.
35. **MC-035 — SLO certification gate.** Turn the contractual p99 target into reproducible benchmark evidence with regression thresholds and hardware/environment metadata.
36. **MC-036 — Large-payload/DoS benchmark suite.** Characterize worst-case CPU/memory for nested lists, records, strings, and invalid inputs and prove quotas fail predictably.

## P1 — Operations and observability components

37. **MC-037 — Metrics emitter.** Emit the contract's boundary call, mapping refusal, range violation, ownership transfer, canonicalization refusal, and encoding refusal counters with bounded cardinality.
38. **MC-038 — Distributed trace instrumentation.** Correlate lower/lift operations with interface, component, source/target language, error code, and duration without leaking sensitive values.
39. **MC-039 — Structured security audit events.** Produce tamper-evident events for mapping-policy changes, failed trust checks, resource ownership violations, and privileged configuration changes.
40. **MC-040 — Diagnostic redaction policy.** Prevent payload values, secrets, tenant data, and oversized attacker-controlled strings from entering logs/errors/metrics labels.
41. **MC-041 — Runtime health/readiness model.** Define healthy/degraded/blocked states for missing mapping profiles, incompatible schemas, runtime faults, quota exhaustion, or dependency failures.
42. **MC-042 — Capacity/fairness controller.** Apply per-tenant/per-workload quotas for concurrent calls, copied bytes, active resources, queues, and streaming windows.

## P1 — Configuration, trust, and supply-chain components

43. **MC-043 — Declarative configuration schema.** Version allowed languages, mapping profiles, resource limits, feature gates, and runtime settings with secure defaults.
44. **MC-044 — Configuration validator/transaction manager.** Validate before activation, apply atomically, retain provenance, and provide deterministic rollback.
45. **MC-045 — Mapping-policy provenance.** Record who/what approved a mapping profile, version, digest, activation time, and environment/site scope.
46. **MC-046 — Artifact provenance verifier.** Verify binding generators, runtime adapters, guest fixtures, and policy artifacts by digest/signature/approved version before use.
47. **MC-047 — SBOM and dependency lock.** Produce machine-readable SBOMs and pinned dependency metadata for the production interop runtime and generated bindings.
48. **MC-048 — Capability/authentication integration.** Bind component identities/capabilities to calls and integrate with the system trust layer without embedding credentials in ordinary interop configuration.
49. **MC-049 — Trust-service outage policy.** Define fail-closed/degraded behavior when identity, attestation, policy, key, or trusted-time dependencies are unavailable.

## P2 — Governance and reproducibility components

50. **MC-050 — Architecture Decision Record.** Record selected Component Model/spec versions, runtime(s), language mapping profiles, no-shared-memory interpretation, BigInt policy, and rejected alternatives.
51. **MC-051 — Formal threat model.** Cover malicious guests, hostile schemas/payloads, compromised bindings/toolchains, resource exhaustion, confused-deputy paths, and control-plane abuse.
52. **MC-052 — Requirements traceability matrix.** Map all 100 checklist IDs to concrete source, tests, runtime evidence, owner, and status instead of relying on inherited/general findings alone.
53. **MC-053 — Reproducible `pk_core` integration environment.** Pin/package the parent framework version and provide a one-command environment that actually executes the full 100-item gate.
54. **MC-054 — CI conformance pipeline.** Run syntax, unit, optimized-mode, fuzz smoke, language matrix, integration, benchmark thresholds, provenance checks, and `pk_core` gating on every change.
55. **MC-055 — Release evidence bundle.** Seal test results, benchmark reports, mapping matrices, SBOM/provenance, configuration digest, and gate verdict into a release artifact.
56. **MC-056 — Compatibility support matrix.** Publish supported runtime, WIT/Component Model spec, language toolchain/binding, OS/architecture, and feature combinations with deprecation windows.
57. **MC-057 — Rollback and emergency-disable runbook.** Define safe rollback of mapping/runtime updates while preserving evidence continuity and preventing mixed-version boundary corruption.
58. **MC-058 — Operational incident playbook.** Provide procedures for mapping refusals, ABI mismatch, corrupted resources, performance regression, isolation breach indicators, and emergency containment.

## Highest-priority completion sequence

For a production-grade next pass, implement **MC-001 → MC-018** first so the semantic model is complete, then **MC-019 → MC-025** so it operates against real runtimes/languages, then **MC-026 → MC-036** to prove safety/performance. The operational, trust, and governance components should be developed in parallel before declaring the element production-certified.
