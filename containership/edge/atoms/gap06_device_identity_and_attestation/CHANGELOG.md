## 5.0.0 - 2026-09-22

Missing-components pass: `GAP06-MISSING-COMPONENTS-CHECKLIST/1` v1.0.0 (781 items, 54 components) applied through the junkyard chop shop. Additive: the v4.2.0 `attestation` API and its tests are unchanged.

### Added (`mc/`, 20 modules, stdlib + `cryptography==46.0.7`)
- `tpm` bounds-checked TPMS_ATTEST / TPMT_SIGNATURE parser, PCR composite recompute, crypto-agile TCG event-log parser with Spec ID validation, data-bound event verification, known-event-type registry, replay and first-divergence; TPM clockInfo monotonicity.
- `verifier` fail-closed quote pipeline with reason codes and evidence records; IMA `ima-ng`; relay channel binding; duplicate-device detection; generic signed TEE report adapter (SVN / debug / TCB / report_data).
- `certchain` EK/AK chain validation (signatures, validity, CA/pathLen, keyUsage, CRL with signature-checked CRLs, fail-closed revocation mode, test-root refusal).
- `enrollment` PoP ceremony, single-use tickets, anti-clone EK/AK uniqueness, old-AK-signed rotation, revoke/replace.
- `store` hash-chained fsync'd WAL, atomic snapshots, torn-tail recovery, restore generation floor; `replay` durable single-use challenges with bounded retention argument and lease/fencing.
- `policy` M-of-N Ed25519 signed measurement policy, monotonic versions, staging, rollout, deny-overrides precedence engine.
- `audit` hash-chained, per-event Ed25519-signed ledger with anchored-head truncation detection; `keys` KMS-shaped keystore with ACLs/rotation.
- `authz`, `transport` (mTLS HTTPS JSON), `schemas` (closed PK_*/1 schemas), `errors` (stable GAP06-ERR/1 catalogue with redaction), `ratelimit`, `clock`, `ops` (quarantine outbox, re-attestation scheduler, offline mode, health, telemetry, explain, sharding, signed config), `workload`, `integrations`, `service` (integrated request path).
- 82 new tests (103 total), `tools/fuzz.py`, `tools/bench.py`, `tools/release.py` (item-by-item status with re-verified evidence, SBOM, signed manifest, mechanical gate).
- Docs: reconstructed `docs/MASTER.md` (clearly marked), threat model, 5 ADRs, runbooks, governance, compatibility, key inventory, generated error/config/observability/capacity references; `SECURITY.md`, `pyproject.toml`, `requirements.lock`.

### Defects found by this pass's own tests and fixed
1. Admission control grew its principal table without bound on rejected requests (hostile principal churn) — `AdmissionTest.test_per_principal_global_and_bounded`.
2. Event-log body bytes were not bound to their digests, so a tampered EV_IPL body verified — `PropertyFuzzTest`.
3. The Spec ID header was only prefix-checked; header bytes could change freely — `PropertyFuzzTest`.
4. Event type codes could be relabelled to unknown values (TCG PCRs bind digests, not types) — now rejected against the PFP registry.
5. Nonce consumption used a CAS on the store-wide generation, so concurrent attestations for *different* nodes failed each other with `E_CONFLICT` — and `ConcurrencyTest.test_parallel_nodes` hid it by only checking threads that finished. Both fixed.
6. `Gap06Error` was a frozen dataclass; raising it inside a context manager crashed with `FrozenInstanceError`.
7. The simulator claimed test-only roots were refused; nothing enforced it. `certchain` now refuses them by default.

### Not done (see `CHECKLIST_STATUS.md`)

## 4.2.0 - 2026-09-22

Security audit, correctness repair, hardening, test expansion, and package-truthfulness pass.

### Trust-boundary fixes

- Replaced deterministic `sha256(environment|node|now)[:16]` challenges with 256-bit cryptographically random nonces generated by `secrets.token_hex(32)`.
- Added explicit node enrollment and revocation; unknown nodes cannot obtain challenges.
- Bound each outstanding challenge to one node and changed validation order so a different node cannot consume/burn that challenge.
- Changed validation order so unissued/self-chosen evidence cannot quarantine or otherwise mutate a node's trust state.
- Added challenge expiry, spent-nonce replay handling, and an outstanding-challenge capacity ceiling.
- Added hardware identity enrollment matching so a bare `hardware_rooted=True` assertion can no longer independently grant hardware trust.
- Added quarantine reasons and revocation invalidation of live verdicts/outstanding challenges.
- Added logical-clock rollback rejection for stateful operations to prevent trust resurrection through backdated queries.

### Evidence and policy hardening

- Added bounded/canonical evidence validation: type checks, non-empty identifiers, maximum lengths/counts, sorted measurements, and duplicate rejection.
- Replaced delimiter-based/truncated evidence binding with canonical JSON + full SHA-256 and environment binding.
- Made `Evidence`, `Challenge`, and `Verdict` immutable slotted dataclasses.
- Added accepted measurement-set version tracking and atomic set replacement; verdicts carry the policy version used.
- Added thread-safe state mutation with an `RLock`.

### Testability and packaging

- Moved the standard-library attestation core to `attestation.py`, allowing security tests to run without `pk_core`.
- Made framework-bound package exports lazy so package/core imports work when `pk_core` is absent.
- Added 17 standalone security/state tests plus package/version checks; tests also pass under `python -O`.
- Preserved the optional framework-wide 100-requirement conformance checks when `pk_core` is installed.
- Corrected README claims about the absent `MASTER.md` artifact.
- Added `AUDIT_REPORT.md` and `MISSING_COMPONENTS.md`.

### Compatibility note

This release intentionally tightens fail-closed behavior: a node must be enrolled before challenge issuance, hardware trust requires a matching enrolled hardware identity, and accepted-measurement mutation carries an explicit version. These are security contract corrections rather than silent compatibility shims.
