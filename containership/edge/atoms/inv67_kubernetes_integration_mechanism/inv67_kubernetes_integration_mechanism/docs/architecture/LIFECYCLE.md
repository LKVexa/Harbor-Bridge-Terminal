# Failure and lifecycle semantics (item 04, C014–C015)

Implementation: `plane/lifecycle.py` (states, legal transitions, error taxonomy, attempt ids, aggregation). The full 14×14 transition table is generated by `lifecycle.transition_table()` and every pair is exercised by `tests/unit/test_lifecycle.py`.

## States

`Requested → Validating → Admitted → Queued → Placed → Starting → Running → Succeeded|Failed`, plus `Cancelled`, `Deleting`, `Degraded`, `Blocked`, `Unknown`. Terminal: `Succeeded`, `Failed`, `Cancelled` (leave only to `Deleting`, or `Failed → Validating` on a new generation).

## Four views, one authority each

| View | Authority | Where |
|---|---|---|
| Desired | user | `spec` (generation) |
| Observed Kubernetes | API server | `metadata` (resourceVersion, deletionTimestamp) |
| Runtime | SCH-01/INV-68 | `observe(appId)` |
| Projected | controller | `status` (phase, state, conditions) |

On disagreement the runtime is authoritative for *what is running*; if the runtime cannot be observed for `staleObservationSec`, the projection becomes `Unknown` (Ready=Unknown, Degraded=True) — never a guessed `Running`.

## Error taxonomy

Stable codes in `lifecycle.ERRORS`: terminal (`PK_K8S_UNSUPPORTED_FIELD`, `PK_K8S_INVALID_POD`, `INV67_UNAUTHORIZED`, `INV67_INCOMPATIBLE`, `INV67_ARTIFACT_UNVERIFIED`, `INV67_QUARANTINED`, `INV67_RUNTIME_FAILED`) and retryable (`INV67_QUOTA_EXCEEDED`, `INV67_DOWNSTREAM_UNAVAILABLE`, `INV67_CIRCUIT_OPEN`, `INV67_OVERLOADED`, `INV67_CONFLICT`, `INV67_FROZEN`, `INV67_NOT_LEADER`, `INV67_STALE_OBSERVATION`). Terminal errors stop retrying until the generation changes.

## Attempts

`attemptId = <uid>/g<generation>/a<attempt>` is the downstream idempotency key. A retry of the same attempt reuses it (journal replay); a new generation always gets a new one, so stale status from an old attempt can't be mistaken for the current run (`observe()` compares `key` to `status.attemptId`; mismatch → `PlacementLost` → re-place).

## Partial success

`aggregate_units`: any unit Failed ⇒ Failed; any Unknown ⇒ Unknown; all Succeeded ⇒ Succeeded; Running+Succeeded ⇒ Running; else the least-advanced pending state.

## Deletion / finalization

Finalizer added before any side effect. On `deletionTimestamp`: journal `cancel` intent → fenced `cancel(appId)` → journal done → remove finalizer. If the runtime is down the finalizer stays (no leak). Force-delete is a human action → orphan runbook.

## Failure ownership

| Failure class | Detects | Retries | Escalates to | Resolves |
|---|---|---|---|---|
| Invalid/unsupported spec | translator | never | user (status/event) | user |
| Unauthorized/unbound ns | controller | never | tenant admin | platform |
| Artifact unverified | controller | never | user / security | user |
| Quota/overload | admission | controller queue (backoff) | SRE if sustained | capacity owner |
| Downstream unavailable | breaker | controller queue only (downstream must not also retry the same envelope) | SCH-01 owner | SCH-01 |
| API conflict/outage | client | controller queue | SRE | platform |
| Stale observation | controller | observe loop | SCH-01 owner | SCH-01 |

**Retry ownership:** only the controller work queue retries. The adapter makes one call per reconcile; SCH-01 is required by `PK_K8S_PLACE/1` to treat the idempotency key as dedupe, not to retry on INV-67's behalf. This prevents nested retry storms.

## Upgrade / downgrade / mixed version

State names and error codes are append-only within `v1alpha1`. An older controller seeing an unknown `status.state` treats it as `Unknown` and re-observes. Rollback of the controller is safe because status is re-derived from the runtime.
