# ADR-0002: Governed service layer around the unchanged safety kernel

- **Status:** Proposed. It needs `pk-architecture-board` approval, and that role has no named holder yet (`ops/OWNERS.md`).
- **Date:** 2026-09-23
- **Scope:** INV-69 v4.3.0, which remediates the 49 controls that the v4.2.0 audit marked as missing.

## Context

The v4.2.0 kernel (`runtime.Agent`) enforced containment. It had no configuration model, lifecycle
state machine, error taxonomy, deadlines or trust gating. It could not interoperate with INV-57, INV-59,
INV-70 or INV-71, and it had no operational surface.

## Decision

1. **The kernel stays the policy enforcement point.** `governed.GovernedRuntime` composes the new
   pieces around it:
   - configuration generations
   - trust gating
   - INV-59 authorization
   - the kernel step
   - precedence-resolved sandbox selection
   - fenced, idempotent dispatch through INV-70 or INV-71
   - the INV-57 checkpoint and effect record
   - a hash-chained `PK_AGENT_RUN_EVENT/1` stream

   Nothing in the service layer can turn a kernel refusal into a run.
2. **The kernel's v1 wire schemas stay closed.** Stable error codes go on the returned result and in
   the new run-event stream. `PK_AGENT_STEP/1` is not widened.
3. **Precedence, dependency criticality, telemetry policy, lifecycle tables, the error registry and
   configuration fields are all data.** `ops/SPEC.md` is generated from that data, and CI fails when
   the two drift apart.
4. **Configuration is applied atomically, one generation at a time.**
   - Each process validates the whole candidate and then switches with compare-and-swap. Provenance
     is recorded in the same critical section.
   - Across instances, rollout is generation-based. Instances may run generation N and N+1 side by
     side, because every event records `config_generation`. Settings that must change atomically are
     locked at `base` or `environment` scope (sandbox tiers, approval requirement, residency), so they
     cannot differ between sites.
5. **Failover is fenced.**
   - A run is adopted only through a new INV-57 fence, and the fence is checked before any side effect.
   - Approvals are never carried across a failover.
   - Committed effect keys are never replayed.
6. **Adjacent layers are reached through contract-faithful adapters** (`sandbox.py`). The real peers
   are not in the candidate archive. The certification tier against them is an explicit, waivable
   gap (W-002), not a claimed pass.

## Consequences

- Invocation latency increases (measured in `evidence/PERF_RESULTS.json`). An in-process invoke is
  still sub-millisecond at p95 on the reference machine.
- The release gate stays `NO_GO` until humans are named, waivers are approved, and pk_core and a
  release approval are supplied.
- Stdlib-only signatures (HMAC) are a stand-in until an asymmetric scheme is approved (W-003).
